# 产品定义与边界

## 一句话定义

OIRO（OTA Intelligent Revenue Officer，OTA 智能收益优化官）是一个站在酒店立场、以利润为目标的 AI 收益运营官。它不是报表工具，也不是聊天机器人，而是持续承担 OTA 收益与排序相关决策、并对结果负责的运营角色。

## 要解决的本质问题

表面问题是价格调了排名仍掉、活动把利润吃光、运营很忙但结果不稳定。本质是：

- 变量过多：价格、房态、转化、流量、竞对、平台规则交织
- 决策非线性：同一动作在不同时间结果完全不同
- 经验无法规模化：优秀运营不可复制

因此产品核心是**连续决策质量**，不是把执行按钮做得更多。

## 明确不做什么（初期）

- 官方 PMS/CRS 仅预留合作方 API 接入（由运维端安装正式契约）；不内置、也不售卖轻量 PMS 或房态工作台，也不声称已对接 Opera / Cloudbeds / Mews
- 新酒店须完成商务电子合同审批并确认付款后，产品权限才生效；电子签与支付供应商尚未接通，只预留运维端契约配置接口。这不是计费产品。内部岗位与开通流程见 [11-内部岗位与开通流程.md](11-内部岗位与开通流程.md)
- 不承诺 100% 自动化
- 不做酒店整体经营决策（只做 OTA 收益与排序相关决策）
- 不做 OTA 平台本身
- 不以境外大模型作为中国生产环境的主链路

## 产品形态

先做**网页版 SaaS 应用**（对标「订单来了」的网页形态，而不是先做桌面端）。桌面端仅作为后续增强：长时间挂机盯盘，或对数据不出酒店特别敏感的客户。默认部署为国内云多租户 SaaS；私有化与“数据本地、推理上云”的混合方案不进入本轮 MVP。

## 商业逻辑（战略层，本轮不实现计费）

客户购买的是持续工作的 AI 运营角色，年费约等于传统 OTA 运营人力成本的 5%–10%。第一层可收费能力是 L3 策略生成，L4 执行替代才是收入核心，护城河在 L5 行业学习。
