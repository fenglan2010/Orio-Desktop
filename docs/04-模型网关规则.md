# 模型网关与适配规则

## 设计

先接通国产模型主链路，同时把统一接口、路由和适配规则定死。境外模型只预留适配器，不进入生产默认路径。

对内只暴露统一协议，业务代码不得直接绑定某一厂商 SDK。统一能力至少包括：聊天、工具调用、结构化输出（JSON schema / 等价约束）。

## 厂商适配

| 适配器 | 角色 | 本轮状态 |
| --- | --- | --- |
| DeepSeek（OpenAI 兼容接口） | 国产主模型 | 启用；无密钥时走确定性模拟器，保证离线可演示 |
| Qwen / 通义（OpenAI 兼容接口） | 国产备用 | 适配器预留并可配置，默认备用 |
| 自建开源模型（OpenAI / Qwen 兼容接口） | 国内第三备用（预留） | 默认关闭；不编造生产地址。在腾讯云或阿里云部署后，填写服务器环境变量即可启用 |
| OpenAI / ChatGPT | 境外对照 | 适配器预留，默认关闭 |
| Gemini | 境外，长上下文与多模态 | 适配器预留，默认关闭 |
| Grok / xAI | 境外，非收益决策首选 | 适配器预留，默认关闭 |
| MockModel | 本地演示与测试 | 始终可用 |

## 必须实现的规则

1. **统一协议**：所有适配器输入输出一致，包含模型名、任务类型、是否允许工具调用、结构化结果、用量与错误码。
2. **按任务路由，不按厂商写业务**：任务类型示例：`analysis`、`pricing_strategy`、`review_reply`、`assistant_chat`、`vision_or_longdoc`。
3. **超时、限流、失败自动降级**：主模型失败则切备用国产官方 API，再失败则切自建开源（若已配置），再失败则切 Mock，并明确告知“当前为降级结果”。
4. **境外模型默认关闭**，需在配置中单独授权开启。
5. **关键动作禁出境**：`pricing_strategy`、`review_reply` 以及任何将导致调价/回复/执行的调用，即使境外模型已开启，也不得路由到境外适配器。自建开源端点视为国内，关键任务可以使用。
6. **审计**：每次调用记录厂商、模型、任务类型、租户/酒店、是否出境、是否降级、时间与结果状态；不得把完整密钥或接口地址写入日志。
7. **酒店不配置路由**：任务偏好、境内外开关、适配器地址和密钥只在服务器环境或内部运维后台可见，不出现在酒店设置页。

## 默认任务偏好（服务器可覆盖）

按模型特长选择顺序，不按厂商写业务代码。未填写环境变量时使用下表。覆盖方式：`LLM_TASK_PREF_<TASK>=deepseek,qwen,self_hosted,mock`（逗号分隔）。未知厂商会被忽略；关键任务即使被写成境外厂商，也会在校验时剔除。

| 任务 | 特长与默认顺序 | 出境 |
| --- | --- | --- |
| `analysis` | 推理与叙事：DeepSeek → Qwen → 自建开源（预留）→ Mock | 仅当境外开关打开且非关键时可追加境外模型 |
| `pricing_strategy` | 定价策略建议：同上 | 禁止出境 |
| `review_reply` | 评价回复草稿：同上 | 禁止出境 |
| `assistant_chat` | 助手对话：同上 | 仅当境外开关打开且非关键时可追加 |
| `vision_or_longdoc` | 长上下文 / 多模态：国内官方 API 与自建开源之后，若境外已开可优先 Gemini，再 OpenAI、Grok，最后 Mock | 仅当境外开关打开且非关键时 |

无密钥或自建开源未配置（`SELF_HOSTED_BASE_URL`、`SELF_HOSTED_API_KEY`、`SELF_HOSTED_MODEL` 任一为空）时，跳过该厂商并继续链路。自建开源是预留接入，不是已经部署好的模型；不要编造腾讯云或阿里云主机地址，部署完成后再填写环境变量启用。

内部运维可在 `gateway.describe(for_ops=True)` / 运维「系统状态」接口看到任务偏好表、限流与熔断状态；酒店 `/api/settings` 不会返回自建开源适配器，也不返回偏好表或熔断细节。

## 排队、超时与熔断（单进程）

当前保护在单个 API 进程内生效，用于避免高并发或厂商故障拖垮 LangGraph 决策流。厂商失败只会使该次调用降级到备用或 Mock，不会抛出未捕获异常中断工作流。

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `LLM_TIMEOUT_SECONDS` | 20 | 单次厂商调用超时，超时后切换下一候选 |
| `LLM_RATE_LIMIT_PER_MINUTE` | 30 | 每厂商每滚动分钟调用上限；`0` 表示不限制 |
| `LLM_VENDOR_CONCURRENCY` | 4 | 每厂商同时进行中的调用数 |
| `LLM_GLOBAL_CONCURRENCY` | 8 | 进程内全局同时进行中的调用数 |
| `LLM_QUEUE_WAIT_SECONDS` | 5 | 槽位不足时在进程内短暂排队；超时则改试下一厂商 |
| `LLM_CIRCUIT_FAILURE_THRESHOLD` | 3 | 连续超时或错误次数达到后熔断该厂商 |
| `LLM_CIRCUIT_COOLDOWN_SECONDS` | 30 | 熔断冷却；结束后半开探测一次，成功则关闭，失败则再次打开 |

这不是跨主机的分布式限流。Docker Compose 或 Kubernetes 多副本要把限额算在整个集群上时，需要后续接入共享限流（例如已有 Redis）。熔断打开、排队超时和调用超时会写入 `ModelCallLog`（`circuit_open` / `queue_timeout` / `timeout`），日志不含密钥。

## 能力分工

- 大模型：理解、归因说明、策略草案、评价回复、对话
- 自研计算（规则 + 统计模型，本轮用可解释的启发式即可）：需求预测、价格区间、约束校验（最低价、竞对带、库存）
- 大模型不得直接输出一个不可复核的最终执行价；必须给出建议区间、推荐值、理由、置信度，交由人审
