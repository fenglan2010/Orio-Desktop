# OIRO 操作运行指南（酒店桌面）

面向已安装 **OIRO Windows 桌面包** 并**已激活安装密钥**的酒店用户。日常数据以**本机配置的 OTA 契约、PMS API 与同步结果**为准；演示酒店账号仅用于培训，不应作为长期经营数据源。

**默认安全策略**：人审为主；低风险自动执行、自动调价、真实 OTA live 写入均为**默认关闭**（见 [配置指南](配置指南.md)）。

---

## 一、启动与停止

### 桌面包（生产主线）

**酒店用户**：**安装 → 打开 → 输入安装密钥 `OIRO-XXXX-XXXX-XXXX` → 登录**（无需安装 Python / conda）。

- 开始菜单或安装后的 `OIRO.exe`。
- 若再次提示安装密钥，检查是否更换了用户配置目录或 `install.state.json` 被删除。
- 关闭窗口会结束后台 API 子进程。同时只应保留一个 OIRO 实例（重复打开会聚焦已有窗口）。

### 从源码（开发，PowerShell 可选）

```powershell
# 开发者：Git Bash / WSL
make dev
```

浏览器 http://127.0.0.1:5173 ，`OIRO_DISTRIBUTION=source`，**无**安装密钥。

### 内置前端一体（源码）

```bash
bash scripts/run-desktop-source.sh
# http://127.0.0.1:8000
```

## 二、首次登录后的配置顺序（真实数据）

建议按以下顺序完成本机配置，再开展 L1–L3 日常运营：

1. **安装密钥**（若未在启动时完成）  
   格式 `OIRO-XXXX-XXXX-XXXX`，见 [配置指南](配置指南.md)。

2. **本机模型密钥** — 系统设置 → 本机配置  
   保存 DeepSeek / 通义等；数据仅存本机加密文件。

3. **OTA 官方连接** — 系统设置 → OTA 渠道  
   - 保存**本店** OTA 账号密码；  
   - 保存合作方提供的**官方契约 JSON** 的本地路径（非 `docs/official-contracts` 示例）。  
   - 成功后 L1/L2 指标与诊断将逐步反映**所连渠道**数据；未配置前勿把演示店 KPI 当作本店实况。

4. **PMS/CRS（如有）** — 系统设置 → PMS 集成  
   契约路径 + 厂商提供的 HTTPS API 基址。

5. **写入与自动执行** — 系统设置 / L4  
   确认自动执行、live 写入仍符合贵司政策（**默认关**）；需要时由授权角色在运维或酒店设置中显式开启。

6. **登录酒店业务账号**  
   使用贵司在系统中创建的酒店用户（非长期使用 `admin` / `admin123` 演示账号）。

运维工作台：`#/ops/login`（内部岗位，见 `README.md` / `docs/11-内部岗位与开通流程.md`）。

## 三、典型工作流（L1 → L5）

1. **L1 实时监控**：查看 KPI、预警（通知过滤规则见设置）。  
2. **L2 多维分析**：生成策略建议；价格区间由可解释规则计算，大模型辅助说明。  
3. **L3 执行中心**：待人审队列、评价回复草案、写入监控（沙盒或官方回执）。**默认须人审。**  
4. **L4 自治管理**：低风险自动执行开关默认 **关**；渠道连接状态只读展示。  
5. **L5 进化 / 审计**：本店经验沉淀；日志不含密钥明文。

决策对话：顶栏抽屉。旧路由会自动重定向。

## 四、写入与安全边界

| 条件 | 行为 |
|------|------|
| 无有效官方契约 | 仅建议与沙盒回执，**不**伪造生产 OTA 成功 |
| 契约有效但 live 开关未开 | 不执行真实调价写入 |
| 评价回复 | **不**自动公开发布 |
| 境外模型开关开启 | `pricing_strategy` / `review_reply` 仍不出境 |

## 五、Windows 故障排查

| 现象 | 检查与处理 |
|------|------------|
| 无法登录 / 503 | `GET /api/install/status` 是否 `blocked`；正式包是否已激活密钥 |
| 安装密钥无效 | 是否为 **三段** 格式 `OIRO-XXXX-XXXX-XXXX`（非四段） |
| Electron **白屏**，8765 返回 JSON 404 | 未打包 `frontend\dist` 到 `resources\renderer`；重新 `.\desktop\scripts\build-windows.ps1` 并确认 `Test-Path ...\resources\renderer\index.html` |
| `spawn python ENOENT` | 安装 Python 3.11+ 或在克隆目录创建 `.venv` |
| 打包失败 / electron-builder 异常 | 改用 **Node 20 LTS**；设置 `$env:CSC_IDENTITY_AUTO_DISCOVERY = "false"` |
| 缺少 `frontend\dist` | `npm run pack:dir` 会先尝试构建；失败时手动 `cd frontend; npm ci; npm run build` |
| SmartScreen 拦截 | 未签名构建预期行为；由酒店安全流程处理 |
| 模型无响应 | 本机配置是否已保存 Key；无 Key 时走 Mock |
| 契约未启用 | 路径是否存在、是否误用 example JSON、`platform` 是否与渠道一致 |
| KPI 仍像演示店 | 是否仍用演示账号或未保存 OTA/PMS 连接 |

**本机 API 自检（开发）**：浏览器或 `Invoke-WebRequest http://127.0.0.1:8765/api/health`（桌面包默认端口以实际为准）。

## 六、停止与重置

- 停止：关闭 OIRO 窗口或结束 Python 子进程。  
- 重置**演示** SQLite 数据（开发机）：`make reset` — **不删除** `model-keys.enc.json` 与 `install.state.json`，除非手动清理 `data/local/`。  
- 生产桌面包：备份用户数据目录后再做重置；避免误删本机契约路径指向的文件。

## 七、从 CI 拉取 PR 分支并在 Windows 重建（维护者）

```powershell
git clone https://github.com/fenglan2010/Orio-Desktop.git Orio-Desktop
cd Orio-Desktop
git fetch origin pull/<PR_NUMBER>/head:pr-desktop
git checkout pr-desktop

python -m venv .venv
.\.venv\Scripts\pip install -r backend\requirements.txt

$env:CSC_IDENTITY_AUTO_DISCOVERY = "false"
.\desktop\scripts\build-windows.ps1 -WithInstaller
```

将 `<PR_NUMBER>` 换为 Pull Request 编号。
