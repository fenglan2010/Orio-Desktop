# 第二阶段说明

第二阶段的目标是：在现有人审闭环上，按风险分级放开部分自动执行，并接通真实 OTA 写入。收费数字不在本阶段锁定。

## 第一增量（已落地）

- 酒店执行策略可保存：自动执行开关（默认关闭）、自动执行最高风险（本增量固定为低）、节假日必须人审（默认开）、调价人审阈值（默认 15%，只可更严）、回滚策略（人工 / 写入失败时自动回退）。
- 开启后，只有最终风险为 `low`、且通过硬规则的策略会跳过等待并执行：调价幅度达到阈值、入住窗口覆盖 2026–2027 年国务院办公厅公布的法定节假日放假调休、活动报名/高佣金、评价回复，一律留在人审队列。
- 自动执行审计操作人为 `system:auto_execute`，包含风险等级、策略快照和 `checkpoint_id`，执行前仍打检查点，可按原回滚路径撤销。
- 写入默认是官方沙盒回执（`sandbox_official`），只在本地记录拟写入内容，不向携程或美团发真实请求。live 模式在缺少 `CTRIP_WRITE_ENABLED` 与凭证时拒绝写入；即便配置了凭证，本增量也不会发起出站 HTTP。
- 酒店设置页和 L4 自治页共用同一套执行策略。模型路由、适配器状态、境外开关和 API 密钥不在酒店用户界面展示。

## 本增量未做、留给后续

- 真实官方 API 出站写入（携程、美团、飞猪）与回执对账
- 执行监控、部分成功处理、超时重试与告警
- 账号权限矩阵、渠道真连接、可单独售卖的轻量 PMS（官方 PMS/CRS API 预留接入已另落地，见运维端与酒店设置）
- 评价回复自动发布、L5 学习、爬虫采集、计费模块

## 第二增量（已落地）

- 增加写入账本（`write_jobs`）：记录拟写入内容、官方形态回执（含 request/receipt id 与房型+日期等行项目）、尝试次数、错误和对账结果。不只依赖策略上的 `execution_payload`。
- 执行节点与自动执行都会创建/更新账本。默认成功路径仍是 `sandbox_official` 且全部接受，演示生成不会随机失败。沙盒可按测试需要模拟 accepted / partial / timeout / failed。
- 对账服务比较拟写入、回执和策略/回复状态，标记回执缺失、已接受但状态未执行、部分残留和价格不一致；提供单条与批量对账接口。
- 超时和瞬时失败可重试，最多 3 次；缺少凭证或未接通官方接口的 live 拒绝不能当作网络错误重试；评价回复不会自动发布，也不会走自动执行重试。
- 若酒店回滚策略为 `auto_on_write_failure`：不可重试的失败立即按检查点回滚；可重试的失败在次数用尽后自动回滚。部分成功留给人工对账，不会自动整单回滚。
- 写入失败、超时、部分成功或对账不一致时，会生成 `write_failed` / `reconcile_mismatch` 预警，诊断文案只谈写入账本，不编造转化或排名故事。
- 执行中心「写入监控」页签和 L4 自治页共用同一账本视图，可看状态、次数、回执模式、最近对账结果并重试。

## 第三增量（已落地）

- 渠道授权：携程 / 美团 / 飞猪可保存连接记录（状态：未连接 / 已连接 / 连接异常，含 `authorized_at`、`last_verified`）。酒店只需授权本店 OTA 账号和密码；账号密码只保存在服务器加密字段，设置页保存后不再回显，GET 接口也不返回原始凭证、契约主机或写入开关细节。官方契约、接口地址、适配器和官方接口密钥由运维端配置。
- 写入走契约驱动的 `OfficialHttpClient`。只有同时满足：(1) 渠道已授权，(2) 服务器有凭证，(3) 该平台写入开关已开，(4) 已配置官方契约（base URL、鉴权、路径、请求/响应映射）时，才会在 `write_mode=live` 下发出真实 HTTP。价格写入优先；若契约包含活动报名也可写活动。评价回复仍然不会自动对外发布，即使人审通过也不出站。
- **公开文档核查结论（未编造接口）**：
  - 携程：未找到稳定、可公开引用的酒店商家调价写入 API。公开价格同步属于玩乐/门票等场景，不能当作酒店 eBooking 写接口。生产 URL 只能来自合作方契约，本仓库不内置。
  - 美团：官方酒店直连平台见 [openplatform-hotel.meituan.com](https://openplatform-hotel.meituan.com)，鉴权为合作方 MWS。公开页提到价格同步，但完整路径与请求体需按合作文档填写，本仓库不猜测生产路径。
  - 飞猪：开放平台有公开网关 `https://eco.taobao.com/router/rest` 与方法 `taobao.xhotel.rates.increment` / `rate.update`（需 AppKey、session、TOP 签名）。该地址仅作为文档/示例引用，默认演示不会加载或请求。示例见 `docs/official-contracts/`（运行时不会自动加载）。
- 无契约、无凭证、未授权或写入开关关闭时，live 会明确拒绝且**不会打开套接字**。超时与 HTTP 5xx 进入既有重试/失败/告警路径；HTTP 4xx 与上述拒绝原因不能当作瞬时错误重试。成功或拒绝回执写入 `write_jobs` 账本并按第二增量规则对账。
- 演示默认仍是 `write_mode=sandbox`、`auto_execute_enabled=false`。普通生成/人审不会随机出站。酒店可在设置里把写入模式改为 live，但打开 live 仍要等运维端已启用官方契约，否则会安全拒绝。
- 设置页与 L4 共用「渠道连接」状态，酒店侧只展示连接状态、官方契约是否已启用，以及已开放动作（如调价 / 活动）。写入监控展示回执模式（官方沙盒 / 真实回执 / 已拒绝）、平台和官方回执号。酒店界面不展示模型路由、适配器细节、境外开关、契约 JSON、接口地址或原始 API 密钥。


## 第四增量（已落地）

- 酒店账号与固定角色权限矩阵已接通，不再是设置页里的示意表。角色为：`admin` 酒店管理员、`revenue_manager` 收益经理、`approver` 调价审批人、`analyst` 运营观察。权限以后端校验为准，前端只负责隐藏或禁用无权限的导航和按钮。无权限的写操作返回 403 和中文说明。
- 演示账号：`admin` / `admin123`（管理员，完整权限）、`manager` / `manager123`（收益经理）、`approver` / `approver123`（调价审批人）、`analyst` / `analyst123`（运营观察）。历史演示管理员已从「收益经理」升级为酒店管理员，以便原有人审和策略测试继续通过。
- 收益经理可以生成、审批并执行/回滚，也可改价格约束、查看审计，但不能管理账号、不能改渠道凭证、不能改执行策略（自动执行、写入模式、回滚、节假日、阈值），避免自行打开 live 或自动执行。调价审批人可以生成并审批，但不能执行或回滚。运营观察只能看 L1–L2（含对话和预警诊断）。
- 管理员可在设置里添加、编辑、重置密码或停用账号（停用优先于删除）。不能停用或降级唯一的酒店管理员。已停用账号无法登录。`GET /api/auth/me` 返回角色和权限标志；接口不会返回密码或密码哈希。
- 本增量未安装生产环境官方契约，演示默认仍是沙盒写入、自动执行关闭。


## 第五增量（已落地）

- 官方写入契约的校验、安装和卸载已从酒店界面移到运维端。酒店 JWT（含酒店管理员）调用 `POST/PUT/DELETE /api/channels/{platform}/contract*` 会得到 403。运维账号通过 `/api/ops/auth/login` 登录后，使用 `/api/ops/hotels/{hotel_id}/channels/{platform}/contract*` 为本店安装合作方契约；`validate` 只做模式校验，不保存、不开套接字；`PUT` 将通过校验的契约写入 `hotel:{id}:official_contract_{platform}`；`DELETE` 只能卸载设置中保存的契约。
- 若当前生效契约来自环境变量或服务器文件目录，运维 API 不会删除该文件，并返回明确说明。加载顺序不变：环境文件 / 目录 / 设置项。`docs/official-contracts/` 下的示例仍不会自动加载；带 `example: true` 的示例也不能安装为生产契约。安装契约本身不会发起出站写入。
- 校验要求：声明 platform 且与渠道一致、auth、至少一个含 method/path 的动作、有效 base_url。非本机地址必须是 https；禁止 URL 中带用户名密码。本仓库不编造携程/美团/飞猪生产 URL，只接受合作方提供的合格契约。
- 酒店侧渠道与设置只返回连接状态、`contract_enabled`、已开放动作的中文标签、最近校验和是否已保存凭证，不返回密钥、请求头、契约全文、主机名、来源路径或写入开关环境变量名。运维端可以看到来源、主机名、动作和写入开关，仍不回显密钥或契约全文。
- 演示默认仍是沙盒写入、自动执行关闭，且不预装生产契约。演示运维账号 `ops` / `ops123` 不是酒店租户账号，不会出现在酒店设置的账号列表中。

## 本阶段仍未做、留给后续（不再属于本增量）

- 以合作方正式契约配置生产环境官方 URL（须由运营商提供，本增量不会编造）
- 可单独售卖的轻量 PMS / 房态工作台；官方 PMS/CRS API 预留接入已由运维端可配置，默认不预装生产契约，也不是已对接 Opera / Cloudbeds / Mews
- 评价回复自动对外发布、L5 学习、爬虫采集、计费模块
