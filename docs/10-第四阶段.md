# 第四阶段

第四阶段要让系统开始沉淀可复查的决策经验，并在可靠之后以匿名方式引用同类酒店的模式。本文件按增量记录已交付范围。**第一增量（本店 Memory Node / 本店经验沉淀）已交付。第二增量（L5 匿名跨店学习 / 匿名行业模式）已交付。第三增量（这次调价实际带来了什么 / 决策后观察复盘）已交付。第四增量（否决/回滚/失败后的观察复盘、本店知识图谱、离线强化学习与进化引擎）已交付。一键迁移策略仍不开放。**

## 第一增量：本店 Memory Node（已交付）

- 工作流在 `execution_node` 之后进入 `memory_node`，再结束。人审否决（或其他终态处置，例如回滚）也会进入 `memory_node`，以便把拒绝结论记下来。仍在等待人审、或已通过但尚未执行时，不写记忆行。
- LangGraph 与等价状态机走同一条节点路径、同一套节点函数。`engine_info()` 把 `memory_node` 列入 `nodes`，`reserved_nodes` 为空。
- 记忆只按 `hotel_id` 读写。杭州演示店（`tenant_key=demo`）与成都演示店（`tenant_key=demo_chengdu`）的记忆互不可见，也不会在下一轮运行中互相引用。
- 表 `memory_records` 在原有结构上补齐查询字段：`run_id`、`strategy_id`、`checkpoint_id`、`approval_status`、`action_kind`（`pricing` / `campaign` / `review_reply`）、`risk_level`、`episode_key`。新行的 `kind` 为 `decision_episode`。`payload` 只记录已有事实：建议摘要、风险、操作者、审批结论、沙盒回执或拒绝结果、写入任务状态、检查点、日期与房型。结果影响字段在本增量仅预留钩子，默认 `outcome=not_measured`、`impact=null`，**不编造同比、准确率或「这次调价带来了多少收入」**。「这次调价实际带来了什么」已在第三增量接上，对照决策时基线做观察复盘，而不是在第一增量编造归因。
- 同一策略（或同一 `run + strategy + 终态`）只写一行，重跑或回放不会重复插入。
- 新一轮运行会加载**本店**近期记忆到状态（`historical_memories`，并据此诚实填充 `historical_strategies`）。分析节点与策略节点可将其引用为「本店近期已执行 / 已否决」上下文。存在记忆不会改变执行策略，也不会跳过人审或自动改价。
- `GET /api/memories`：需登录，权限沿用 L5 已有的 `view_l5`，只返回当前酒店记录，最新在前，支持 `limit` / `offset`。非本店成员为 403 或看不到该店数据。本增量不提供酒店用户侧的写入或删除学习引擎接口。
- L5 页展示本店经验沉淀列表，不再使用「进化事件日志（示意）」假数据。转化率曲线仍使用本店近 14 日实际指标。跨系统迁移、进化引擎开关、发明新策略、进入沙盒模式保持不可用。时间线节点文案为「经验沉淀」，去掉「预留」。
- 演示默认不变：`auto_execute_enabled=false`、`write_mode=sandbox`，不预装生产官方契约，不编造携程 / 美团 / 飞猪生产 URL。酒店设置页仍不展示模型路由、适配器、境外开关或密钥；酒店只需授权本店 OTA 账号和密码，官方契约和接口由运维端配置。

## 第二增量：匿名跨店学习（已交付）

- 本店终态决策写入 `memory_records` 时，同时向上插入一条**匿名行业模式**（表 `industry_patterns`）。模式键只哈希去标识特征：动作类型、已有信号类型、风险等级、终态分桶（已执行 / 已否决 / 已回滚 / 执行失败 / 部分执行）、以及在已有事实时的价格方向（涨 / 降 / 不变，不含金额）。定位分桶（如「精品」「商务」）仅在同模式的其他酒店可共享时用于展示，不写入模式键，也不保存城市或酒店名。
- 贡献关系写在私有表 `industry_pattern_contributions`，仅用于 k 匿名与自排除计数，**酒店用户侧接口永不返回酒店 id 或贡献名单**。同一本店 episode（同一 `episode_key`）不会重复计数。
- 可见性：只有至少两家酒店贡献了同一模式时，才作为「行业模式」展示；当前酒店看到的计数排除本店身份。仅一家酒店拥有的模式，既不展示给其他酒店，也不对本店伪装成同行经验。因此杭州在成都也有匹配 episode 后可以看到该模式，反之亦然。
- 可识别数据不得跨店：`GET /api/memories`、`memory_records` 行，以及新一轮运行的 `historical_memories` / `historical_strategies` 仍严格限于本店。跨店学习只通过单独的状态字段 `peer_patterns`（同时写入 `industry_patterns` 别名）提供匿名聚合。
- 分析节点与策略节点可将可见模式引用为「同类酒店在类似信号下曾执行 / 否决类似动作」。存在行业模式不会改变执行策略，不会跳过人审，也不会打开自动执行或线上写入。
- `GET /api/memories/patterns`：需登录且具备 `view_l5`，只返回当前酒店可见的匿名模式，按同行片段数、最近贡献时间排序。响应不含酒店 id / 名称、`tenant_key`、地址、城市、精确价格、房型名、评价原文、客人个人信息、检查点 id、策略 id 或其他酒店的操作者姓名。默认 `outcome=not_measured`，不编造同比、准确率或收入提升，也不展示可识别的本店复盘数字。
- L5 页新增「匿名行业模式 / 跨店学习」列表，保留本店经验沉淀和近 14 日本店转化率。文案明确：跨店学习已开始，但是匿名模式，不展示其他酒店名称，不会训练模型，不会自动改价。跨系统迁移、进化引擎、发明新策略、进入沙盒模式仍然不可用；一键迁移不开放，以免带出其他酒店身份。跨店学习是匿名模式引用，不是复制其他酒店的在用策略。
- 本增量不实现知识图谱、强化学习，也不在酒店设置页增加模型路由或贡献开关。效果观察复盘见第三增量，且不写入行业模式。默认仍是每家酒店只贡献匿名特征，自动执行关闭，写入模式为沙盒，不预装生产契约，不编造官方生产 URL。

## 第三增量：决策后观察复盘 / 「这次调价实际带来了什么」（已交付）

- 调价或活动的决策片段在首次写入时，会按当时已知的酒店、入住日期范围和房型，把当时的打包指标快照为基线：OCC / ADR / RevPAR / 客房收入 / 已售 / 可售 / 订单 / 点击 / 转化，并标明每个入住日在决策时是已实现、在途还是在手订单（OTB）。缺少指标时如实记录，不编造数字。此时 `outcome` 仍为 `not_measured`，`impact` 仍为 `null`。
- 采集任务（沿用第三阶段既有任务队列 / 采集节奏，不另建编排栈）在指标更新后，会重读同一入住窗口并写回同一行：已实现入住日对照决策时基线的观察变化；尚未实现的入住日只对照在手订单变化 / OTB pickup，不得写成已实现客房收入或预测。混合窗口把已实现与仍为 OTB 的切片分开，`outcome=partially_measured`；整段入住窗口都实现后才是 `outcome=measured`。若仍无可用指标，保持 `not_measured`。
- 第三增量当时只自动复盘 `executed` 或 `execution_partial` 的调价 / 活动。否决、回滚与执行失败的观察复盘已在第四增量接上。不会把复盘写到另一家酒店的记忆行。匿名行业模式（`GET /api/memories/patterns`）仍保持匿名，且不展示可识别的复盘数字。
- 若策略在提出时已保存 `expected_impact`，复盘会用这些已存字段做「建议情景 vs 观察值」对照，不编造情景、评分或上年同期目标。
- 文案与字段不宣称因果：只写相对基线或相对已记录情景的观察变化。不出现同比、上年对照、准确率或「带来了多少因果收入」。也不用竞对数据充当基线。
- `GET /api/memories`（需 `view_l5`，仅当前酒店）在有复盘时返回 `outcome` 与 `impact`；也提供单条读取。不提供酒店用户侧写入复盘数字的接口。测量只在服务端进行。决策时基线不会被后来的指标覆盖；重复测量只更新同一行。
- L5 页在相关记录上展示「这次调价实际带来了什么」，未复盘则显示「尚未复盘」并说明等待入住日实现或后续在手订单变化，不展示占位假数字。第四增量起，否决 / 回滚 / 执行失败也会复盘，标题改为「否决后实际发生了什么」等。进化引擎、发明新策略、进入沙盒模式已在第四增量接通（默认关闭）；一键迁移策略仍不可用。

## 第四增量：否决/回滚/失败复盘、本店知识图谱、离线强化学习与进化引擎（已交付）

- 调价或活动在 `rejected`、`rolled_back`、`execution_failed` 终态下，也会按与已执行记录相同的诚实窗口规则记录决策时基线，并在采集后对照已实现入住日或在手订单变化做观察复盘。`review_reply` 仍不按调价入住窗口自动复盘。文案必须区分路径：标题为「否决后实际发生了什么」「回滚后实际发生了什么」「执行失败后实际发生了什么」，含义是价格未被改动 / 回滚之后 / 写入失败之后实际发生了什么，不是「这次调价带来了收入」。复盘载荷带上 `terminal_status` 与 `observation_kind`，方便界面措辞。观察值仍不是因果收入，也不是同比。
- 本店知识图谱（表 `graph_nodes` / `graph_edges`）按 `hotel_id` 隔离，从已有事实重建：房型、信号类型、决策片段、动作类型、终态、已复盘的观察结果，以及当前酒店可见的匿名行业模式（只存 `pattern_key`）。关系包括：由信号触发、针对房型、终态、观察结果、相似于可见匿名模式。写入或复盘后幂等重建，不提供酒店用户侧手绘边的写入接口。`GET /api/evolution/graph` 需 `view_l5`，只返回当前酒店；跨店不可见。L5 展示真实节点与关系，不用占位假数据。
- 离线强化学习是本店表格 / 情境学习，不是线上深度强化学习调价器。情境只使用已有事实：动作类型、信号、风险、价格方向；动作桶包括涨价 / 持平 / 降价，以及否决后的「不改价」、回滚、写入失败。奖励是相对决策时基线的观察变化：优先已实现入住日客房收入变化，否则用 OTB 已售间夜变化，从不使用同比，也不把其他酒店的奖励当作标签。样本不足时如实说明，不编造有把握的策略。拟合挂在既有采集任务之后。`GET /api/evolution/rl` 需 `view_l5`，仅当前酒店。用户接受或「发明」的建议若进入工作流，仍走人审，不会自行执行。
- 进化引擎在 L5 页接通，默认关闭。开关与沙盒模式需要已有的 `update_policy` 权限（演示里即酒店管理员）；收益经理可查看，不能开关。分析员沿用既有权限，不能查看 L5，也不能开关。开启后的含义是：进化引擎已接通，但只在本店经验上做离线学习与建议，不会训练跨店可识别模型，不会跳过人审，不会自动改价，也不会改为线上写入。关闭时仍可查看图谱与记忆，但不能发明新策略或进入沙盒评估。「发明新策略」根据本店离线策略生成候选；证据不足时返回诚实的空 / 不足状态，不编造策略。涨价、降价或持平建议可进入普通待人审队列，不会自动执行。「进入沙盒模式」只是 L5 评估开关，用已存基线与观察奖励做对照预览，不把酒店全局 `write_mode` 改为 live，不打开自动执行，不调用线上官方接口。退出沙盒后这些默认保持不变。转化率曲线仍是本店近 14 日实际转化率，不是模型准确率。酒店设置页仍不展示模型路由。一键迁移策略保持禁用，以免带出其他酒店身份。
- 演示默认不变：`auto_execute_enabled=false`、`write_mode=sandbox`、进化引擎默认关闭，不预装生产官方契约，不编造官方生产 URL。

## 仍未包含（留给后续，尚未开始）

- 一键迁移策略，或其他会带出酒店身份的跨店复制
- 区域收益模型、在其他酒店可识别数据上训练模型，或把离线表格学习宣传成深度强化学习调价器
- 官方生产契约就位后的真实 OTA 写入、可单独售卖的轻量 PMS。官方 PMS/CRS API 预留接入已由运维端可配置：酒店侧只看连接状态、契约是否启用和已开放动作，必要时只填写账号和密码；示例契约不会自动加载，本仓库不编造 Opera / Cloudbeds / Mews 等生产 URL，默认不打开自动执行或线上写入。
- 评价回复自动发布、爬虫采集、计费

## 官方 PMS/CRS API 预留接入

PMS/CRS 仍是计划中的主数据来源，但只通过运维端安装的合作方正式 API 契约接入。本增量接通的是预留钩子和配置面，不是完整的 PMS 产品，也不是「已经对接 Opera」。

- 运维端为本店校验、安装或卸载正式契约，配置接口主机、开放动作、官方接口凭证和读写开关。
- 酒店设置 · PMS集成只显示连接状态、契约是否已启用、已开放动作和最近校验；如需本店授权，只填写账号和密码，凭证保存在服务器且不回显。酒店 JWT 不能校验、安装或卸载契约。
- 采集任务在正式契约已启用、凭证可用且读取开关打开时，才按契约拉取库存/房态、房型和在手订单；否则安静跳过（`not_configured`），不覆盖演示用的 OTA 指标。
- 演示默认不变：自动执行关闭、沙盒写入、不预装生产契约，一键迁移仍禁用。不内置可单独售卖的轻量 PMS 或房态工作台，也不使用爬虫。内部运营后台已按岗位分区，商务电子合同与官方 OTA/PMS 契约安装分开；电子签与支付供应商尚未接通，见《内部岗位与开通流程》。
