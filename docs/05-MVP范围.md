# MVP 范围与实现约定

## 目标

做出一个可以本地一键启动、用演示酒店完整走通“看见问题 → 看懂原因 → 给出策略 → 人审 → 留下执行记录”的网页应用，用来验证 OIRO 的产品形态，而不是一次做完全部功能全景。

## 做

- 简单登录与演示租户（默认账号即可，无需完整用户体系）
- 经营看板：营收、可售房/预订率、转化、搜索排名、竞对价格带；数据来自携程模拟适配器
- 智能预警：至少覆盖排名下跌 `rank_drop`、转化异常 `conversion_drop`、价格倒挂 `price_inversion`，并可含差评与竞对调价
- 诊断：对一条预警或某个入住日（今天及更早）给出因果拆解（短期波动 vs 结构问题）；缺少独立数据的维度保持空态，不编造同比或分渠道损益
- 定价策略建议：房型 + 日期范围的价格区间、推荐值、理由、置信度、预期影响；可提交人审
- 活动参与建议（是否跟活动、原因、风险）
- 评价监控与回复草稿，人审后记为“已执行/已拒绝”
- 运营对话助手：用自然语言查数、解释预警、追问某条策略
- 人审队列与审计日志；已执行策略可回滚（状态回退并留痕，本轮不打真实 OTA）
- 系统设置页（酒店用户侧）：调价审批权限、预警通知、房型价格约束上下限；模型路由、适配器状态和境内外开关仅作内部运维，不在酒店用户侧展示。关键动作禁出境规则仍由服务端强制执行，并有自动化测试
- 决策路径追溯：每条策略可见经过的节点、风险等级、检查点与审批记录
- 演示数据要能讲出故事：例如近几日排名下滑、竞对降价、出现一条差评，系统据此给出可人审的策略

## 不做

- 真实对接携程/美团/飞猪开放平台
- 可单独售卖的轻量 PMS / 房态工作台、支付、供应链、金融服务；官方 PMS/CRS API 预留接入已由运维端可配置，但默认不预装生产契约，也不是已对接某一家 PMS 产品
- 桌面客户端、小程序、私有化安装包
- 全自动调价、自动对外发送评价回复
- 一键迁移策略、区域收益模型、融资模块、多租户计费（本店经验沉淀、匿名行业模式、决策后观察复盘、本店知识图谱、离线强化学习与默认关闭的进化引擎已在第四阶段交付，见《第四阶段说明》；观察变化不是因果收入；进化引擎只做本店建议，不跳过人审，不自动改价）

## 技术选型

- 前端：Vue 3 + Vite + Vue Router，中文界面，专业酒店运营后台风格（冷静、清晰、避免花哨）
- 后端：Python 3 + FastAPI
- 工作流：优先 LangGraph；否则等价状态机
- 数据：SQLite（`data/oiro.db`），启动时种子数据可重复导入但不得打断已有人审记录（提供 reset 脚本）
- 运行：提供 `scripts/dev.sh` 或 Makefile，一条命令同时拉起前后端；默认前端端口 5173，后端 8000
- 配置：`.env.example`，用环境变量配置模型密钥和开关

## 验收标准

- 无境外密钥、无国产密钥时，也能完整演示主流程
- 关键动作在境外模型开启时仍不会被路由出境（需有自动化测试）
- 人审通过/拒绝/回滚均有审计记录
- README 说明启动方式、默认账号、哪些是模拟数据
