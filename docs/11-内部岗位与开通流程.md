# 内部岗位与酒店开通流程

本文记录已约定的内部职责分工、商务开通主流程，以及内部运营后台（`#/ops`）的岗位权限与界面分区。电子签和支付供应商**尚未接通**；本轮只落下配置接口、状态机、产品开通闸门和可登录的内部岗位。这不是计费产品。

## 开通主流程

新酒店不能由管理员直接开通产品权限。必须按下面五步走完，酒店账号才能使用分析、渠道授权、策略建议等产品能力：

1. **运营（兼 BD）发起**，并与酒店签署电子合同
2. **合同岗确认**后，合同进入**逐级审批**
3. 双方合同**生效**
4. **确认付款**（预留状态钩子，不是支付通道或收款对账产品）
5. 付款完成后，才**开通这家店的产品能力 / 后台权限**

状态可查询，顺序为：

`initiated`（已发起）→ `signing`（签署中）→ `pending_approval`（待逐级审批）→ `contract_effective`（合同已生效）→ `payment_pending`（待确认付款）→ `payment_confirmed`（付款已确认）→ `product_enabled`（已开通）

官方 OTA / PMS/CRS 契约安装，以及打开官方读取或线上写入，是商务开通**之后**的另一步运维配置，不要和商务电子合同混成同一步。

演示酒店（杭州西湖精品酒店、成都春熙商务酒店）在种子数据中已经是 `product_enabled`，可直接登录使用。默认仍是 `auto_execute_enabled=false`、`write_mode=sandbox`，一键迁移保持禁用。新的非演示酒店在付款确认并开通之前，服务端会拒绝产品接口（`/api/auth/me` 与设置页只读接口除外，用于展示「尚未开通 / 已开通」）。

## 内部岗位（生产可登录）

产品设计**不是**生产运维后台岗位，不会出现在可登录角色中；看需求或做界面时使用演示 / 测试环境。财务计费岗预留，本轮不作为可登录岗位，也不开通计费产品。

| 岗位 | 演示账号 | 职责 | 明确不能做的事 |
| --- | --- | --- | --- |
| 管理员 | `ops` / `ops123` | 管理内部员工账号和授权，查看操作审计，紧急停用账号；付款确认后可开通产品权限；参与线上写入的双人确认 | 不日常安装官方契约或配置官方密钥；不发起商务开通；不能单独打开线上写入；不能跳过合同与付款直接开通 |
| 合同 | `ops_contract` / `contract123` | 审核 / 逐级审批商务电子合同；为指定酒店校验、安装或卸载官方 OTA / PMS/CRS / 电子合同契约，并保存官方接口凭证 | 不能管理员工账号；不能单独打开线上写入 |
| 系统运维 | `ops_sysops` / `sysops123` | 查看部署、模型网关、任务队列等系统状态 | 不安装商务或官方 API 契约；不查看酒店密码或官方密钥；不管理员工 |
| 运营（兼 BD） | `ops_operations` / `operations123` | 发起开通并跟进连接 / 授权进度，催酒店完成账号授权 | 不能看官方密钥；不能安装 API 契约；不能打开线上写入；不能管理员工；不能直接开通产品权限 |
| 客服 | `ops_support` / `support123` | 只读查看开通状态、连接状态和写入失败，协助酒店操作 | 比运营更窄：不能发起开通，不能改任何配置，不能管理员工 |

打开某家店的**线上写入**，须管理员与合同岗双人确认，任何一方单独操作只会留下待确认请求，不会立即生效。官方 PMS/CRS **读取**开关可由合同岗配置，仍须已启用正式契约和凭证才会出站。

研发不作为常驻后台角色。演示账号 `ops` / `ops123` 就是管理员（兼容早期单一 `operator` 角色，启动时会升级）。这些账号都不是酒店租户，不会出现在酒店设置的账号列表里。酒店 JWT 访问 `/api/ops/*` 或电子合同安装接口一律 403。

## 内部运营后台（`#/ops`）

工作台按岗位显示区块，前端只负责隐藏，**权限由 API 强制执行**：

- **商务开通**：开通状态机、发起 / 签署 / 审批 / 付款确认 / 开通权限；合同岗可在此安装官方电子合同预留契约
- **酒店状态**：只读连接状态、开通状态、写入失败；管理员也可在此参与线上写入双人确认
- **官方 OTA 契约**：合同岗安装 / 卸载官方 OTA 契约、配置官方凭证；写入开关走双人确认
- **官方 PMS/CRS 契约**：同上，读取开关由合同岗配置
- **员工与岗位**：仅管理员，含岗位权限矩阵、创建 / 改岗 / 紧急停用
- **操作审计**：仅管理员
- **系统状态**：系统运维与管理员可看环境、数据库类型、队列和网关（不含连接串或密钥）

## 电子合同预留接口

官方电子合同契约的安装方式与 OTA / PMS 相同，只走运维端：

1. 环境变量 `OIRO_OFFICIAL_ESIGN_CONTRACT` 指向的 JSON 文件
2. 目录 `OIRO_OFFICIAL_ESIGN_CONTRACT_DIR/esign.json`
3. 服务器配置项 `hotel:{id}:official_esign_contract`（合同岗校验后安装或卸载）

`docs/official-contracts/esign/` 只放格式示例，带 `"example": true` 且 `base_url` 为空，**不会被自动加载**，也不能当作生产契约安装。本仓库不编造电子签或支付生产环境 URL。出站 HTTP 仅在「已启用非示例正式契约 + 官方凭证 + 明确打开出站开关」时发生；否则安全拒绝，开通单保持 `not_configured` / `waiting_vendor`。演示默认关闭供应商出站。付款确认只是运维状态钩子，不是支付通道对接，也不是计费模块。
