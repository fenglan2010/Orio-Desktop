# 已定决策与待校准项

## 本轮已定（以实现和文档正文为准）

- 产品形态：先做网页版，不做桌面端为首发
- 主市场：中国；国产模型做主链路
- 控制流：状态机 + 人在回路；用 LangGraph 实现，框架可替换
- 模型：先做国产适配，预留 GPT / Gemini / Grok 接口与规则，默认关闭
- 数据源：MVP 用模拟 OTA 数据，接口层按可替换适配器设计
- 官方 PMS/CRS 只走运维端安装的合作方正式 API 契约（预留接入），不承诺 100% 自动化，也不内置轻量 PMS
- 新酒店开通主流程：运营发起并与酒店签电子合同 → 合同岗确认后逐级审批 → 双方合同生效 → 确认付款 → 开通产品权限。官方 OTA/PMS 契约安装是开通之后的另一步。电子签与支付供应商尚未接通。内部岗位见《内部岗位与开通流程》

## 原始文档中尚未校准（本轮先记下，不据此实现）

- MVP 周期：白皮书多为 0–3 个月，全面解决方案写过 0–6 个月；本轮按“可演示的 L1–L3 + 最小 L4 闭环”计，不按日历承诺
- 市场规模：白皮书 SAM 约 100 亿/年，全面解决方案按年服务费测算为 20–30 亿/年
- PMS：文档②写初期不对接，全面解决方案与功能全景已写进集成；现已落地官方 API 预留接入与运维端契约配置，仍不是可单独售卖的轻量 PMS，也未对接 Opera / Cloudbeds / Mews 生产环境
- 原始文档编号中提到的①技术路线图、③④融资叙事、⑤阶段推演等篇目，本次五份材料并未全部齐套
- 全面解决方案中的创始团队为化名示例，不写入产品

## 演示租户约定

- 酒店：杭州西湖精品酒店（演示）

## 来自《总体规划》的待校准（不进入本轮实现）

- 商业模式：总体规划写「SaaS + 收益分成」，已定主模式为订阅制；分成是否引入待定
- 价格：总体规划阶段 II 为 ¥2000–5000/月/酒店，与早期年费方案不一致
